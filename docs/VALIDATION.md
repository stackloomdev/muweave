# 当前验证：完整浏览器版本

2026-09-23。应用运行层已移除 Fastify、Node 文件存储、原生 FFmpeg 和无头 Chromium。Vite 仅提供静态资源；尚未执行公网部署。

- 类型检查、19 项 core / IndexedDB 测试、生产构建通过；包含事务回滚、持久去重、跨连接并发、撤销/重做、素材原子写入、冻结快照、取消后终态保护和非法导出参数。
- 7 项真实 Chromium 端到端测试全部通过（约 30 秒）。覆盖真实文件选择导入音频/图片、测量与静音建议、图层拖拽和缩放、场景删除/撤销、Google 字体、4:3 PNG、SRT 下载和 ZIP 往返。
- 实际浏览器 MP4：1920 × 1080 / 30 FPS / 4.2 秒 / 126 帧，H.264 + AAC，浏览器完整解码和元数据检查通过；测试工具另以原生 FFprobe 和全片解码独立复核。2 秒编码批次和 2.1 秒场景边界附近均有连续音频能量。
- 字体与视频专项禁止 `/api/` 和站外 HTTP 请求仍通过；素材来自 IndexedDB Blob，静态字体、Worker、WASM 从同源加载。
- 导出期间编辑不改变快照；跨标签取消、立即重试、同 ID 错误参数重试不解锁、刷新后成品可预览/下载、活动页面不被误判关闭、关闭后任务标记中断均通过。
- 独立只读审查发现并修复请求锁归属和 MP4 误带封面参数问题；额外修复终态预检跨 await 的清锁竞态，最终再通过类型、构建和完整 WASM 专项。
- 旧磁盘目录三个工程已通过只读迁移脚本生成独立工程包，源工程、历史和成片没有修改。

内置浏览器生产构建验收：旧业务进程已停止，原 4175 端口只运行 Vite 静态预览。原生 WebMCP 实际发现 16 个工具并成功执行能力查询、文件选择交接、浏览器 WAV 解码/测量、素材事务和撤销。三个旧工程均通过浏览器文件选择导入；原 FLAC 配音保留哈希、时长和微秒时间轴，`project.validate` 无问题。

同一中文三页配音示例，在无业务后端的生产页面中由 WebMCP 发起 MP4 导出：398 帧 / 13.2667 秒 / 1920 × 1080 / H.264 + AAC；浏览器生成及完整检查耗时 22.5023 秒，core 加载 0.2528 秒，826,013 bytes（约 0.79 MiB）。7 个批次，最大暂存 PNG 11,878,440 bytes。成品保存到 IndexedDB，通过 Blob URL 在页面预览；播放器实测 `videoWidth=1920`、`videoHeight=1080`、`readyState=4`、时长 13.266667 秒，无页面错误。未据此宣称长片听感或全部浏览器兼容已验证。

仍未验证：公网 Vercel 部署、长项目总内存、移动端/Safari/Firefox、完整十页配音项目听感。构建仍有主 JS 超过 500 kB 提示；WASM 首次原始下载约 31 MiB。公开分发的 ffmpeg.wasm 许可与对应源码打包仍需发布前完成。

## 原生 WebMCP 实机

通过 Codex Browser 插件控制内置浏览器打开本地工作台，实际发现页面注册的 15 个工具。没有安装 `modelContext` polyfill，也没有以直接调用私有页面对象代替工具执行。

验证过程：

1. 原生工具创建独立验证工程，读取场景及标题节点。
2. `node.update` 修改标题，回读文字变化且字号仍为 106；撤销后 revision 从 1 变为 2。

5. 重启运行服务、重新发现工具，在原创示例上调用 `project.validate` 返回空问题列表。
6. 原生 `export.start` → `jobs.get` 完成一张 1920 × 1080 PNG，状态 `succeeded`，revision 与提交一致。

## 输出检查

自动化媒体 fixture 是一段实际生成的 4 秒 WAV：开头约 300 ms、句内约 350 ms、结尾约 500 ms 静音。导入后测量时长为 4,000,000 µs。首尾分析保留起止安全余量，不删除句内停顿。该 fixture 验证时间与媒体管线，不代表完整真人口播试听。

4:3 PNG 实际文件尺寸为 1440 × 1080。工程包重新导入后获得新 ID，两个素材和裁剪后的字幕保留。取消测试等待编码产生非零进度后再取消，随后另一个 PNG 导出成功。

## 发现并修复

- Zod 部分更新中的默认值曾可能覆盖未修改属性，已改为移除默认值后构造 patch schema，并加回归测试。
- 等比图片显示偏移可能混入拖拽坐标，改为固定逻辑框绘制，并通过真实鼠标拖拽测试。
- 同时变换多个节点改为合并提交，避免各节点争抢同一版本。
- 固定场景时长时，裁剪同一音频也会同步字幕；编码取消时处理 stdin 关闭事件。
- 导出读取快照的素材接口，避免编辑中的撤销影响正在导出的素材解析。
- 初次端到端测试在最后的同名按钮定位处超时，已限定工程选择对话框；修正后 3 项全部通过。

## 浏览器 ffmpeg.wasm 导出试用

2026-09-23：`@ffmpeg/ffmpeg 0.12.15` + 单线程 `@ffmpeg/core 0.12.10`。生产构建把 worker、core JS 与 WASM 放在同源静态资源中，按需加载。当前仍需要本地 runtime 提供工程、素材导入处理、快照和成片落盘；不是纯静态部署验收。

- `pnpm check`：类型、15 项核心/服务测试、生产构建通过。新增冻结版本、runner 归属、取消后终态保护与升级前导出请求去重回归。
- 全部 7 项 Playwright 浏览器测试通过，用时约 30 秒。最后对导出锁归属和预览布局作了小修正，再次通过类型、构建、WASM 专项测试及格式检查。
- WASM 专项使用实际图片、中文、字幕和 48 kHz 连续音频，生成 4.2 秒 / 126 帧 / 1920 × 1080 / H.264 + AAC MP4。另用本机 FFprobe 与完整解码复核帧数/时长，并检查 2 秒编码批次、2.1 秒场景边界两侧的 PCM 能量，没有引入额外静音。
- 导出期间修改画面，成片仍绑定已冻结版本。阻断非本地网络后仍成功加载字体与 WASM。编码中取消、图片响应挂起时取消、立即重新导出成功，未出现页面异常。
- 审查后增加 job 图片缓存清理、AbortSignal 网络取消、按请求归属释放导出锁，避免重复导出的资源和锁残留。约 24 MiB 阈值只覆盖 PNG 批次，不能当作浏览器总内存。
- Core 0.12.10 的 ffprobe 在完整输出 JSON 后出现返回 -1 的退出行为；当前先严格完整解码，再校验探测 JSON 的帧数、帧率、尺寸、音视频编码与有限时长，不能仅凭 JSON 文件存在视为成功。

Codex 内置浏览器通过原生 WebMCP 实际完成 `app.get_capabilities`、创建独立中文配音示例、版本化配音/字幕命令、`project.validate`、`export.start(engine=wasm)` 和 `jobs.get`。样例采用系统 Tingting 合成的三句测试语音与原创三页画布，按音频实测时长设置场景，没有添加页间停顿。样例保存在本地工程目录，未加入源码。
